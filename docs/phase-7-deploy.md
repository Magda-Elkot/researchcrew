# Phase 7 — Deployment and README

**Status:** high-level. This gets a detailed plan when the phase starts. [Back to master plan](PLAN.md)

## Goal
**Free tools only, no card** (DECISIONS #48–50). A public **static** demo page (HF static Space or
GitHub Pages) plus a polished README; the live system runs locally with docker compose, and can be
shown live through a temporary free Cloudflare quick tunnel. It builds on the Phase 2b spike results.

## Scope
- **Final pass on all Dockerfiles:** multi-stage, non-root, healthchecks. `.env.example` is complete.
- **Static demo page** (free): example reports (EN + AR) generated by the real system, architecture
  diagram, eval results, Langfuse screenshot, demo GIF. Hosted on a free HF static Space or GitHub Pages.
- **Live demo (optional, free):** `docker compose up` locally + `cloudflared` quick tunnel to Streamlit,
  only while presenting. (The single-container approach from Phase 2b stays available in `deploy/demo/`.)
- **Protecting the shared keys** while a tunnel is open (there's no auth, which is a SPEC non-goal):
  - a global daily run limit and a per-client cooldown, both configurable
  - when the limit is reached, the UI shows pre-generated example reports (EN + AR) instead of starting a run
- **Deploy instructions:** in `docs/deploy.md`.
- **README:**
  - the problem
  - a Mermaid architecture diagram
  - agent roles
  - how MCP is used (ready-made and custom servers)
  - setup
  - the eval results table
  - a Langfuse trace screenshot
  - a demo GIF
  - limitations and next steps (including the free-tier limits, temporary storage, and PyMuPDF's AGPL licence with pypdf as the alternative)

## Key files
- `site/` (the static demo page)
- `README.md`
- `docs/deploy.md`
- `docs/assets/`
- `examples/` (pre-generated reports)

## Definition of done
The free static demo page is online, the live system runs locally (and through a quick tunnel when needed), and the README has the diagram, results table, screenshot and GIF.
