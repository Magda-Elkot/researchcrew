# Phase 1 — Project skeleton, config, Docker, CI (detailed)

**Status:** planned. [Back to master plan](PLAN.md)

## Goal
Lay a clean foundation with no AI logic yet:
- reproducible dependencies
- typed config
- JSON logging
- all data contracts
- a placeholder API with `/health` and `/metrics`
- Docker (api + Qdrant)
- lint/type/test tooling
- a GitHub Actions CI

## Definition of done
- `docker compose up --build` starts `api` + `qdrant`, and both report healthy.
- `curl -f localhost:8000/health` returns 200.
- `uv run ruff check .`, `uv run mypy app mcp_servers` and `uv run pytest` all pass locally.
- CI is green after you push.

## Concepts explained before coding (3–5 sentences each)
uv and lockfiles, pydantic-settings, multi-stage non-root Docker images, GitHub Actions workflows.

## Files to create

### Project & tooling
- `pyproject.toml`:
  - Python `>=3.12,<3.13`.
  - Script entry point `researchcrew = app.cli:main` (a stub for now).
  - Exact versions come from `uv add` at implementation time and are copied into `DECISIONS.md`.
  - Dependency groups keep the api image slim:
    - **core:** crewai, crewai-tools[mcp], mcp, litellm, fastapi, uvicorn[standard], pydantic, pydantic-settings, httpx, qdrant-client, prometheus-client, tenacity, langfuse, openinference-instrumentation-crewai, openinference-instrumentation-litellm
    - **docs:** sentence-transformers, pymupdf, CPU-only torch (from the pytorch-cpu index via `[tool.uv.sources]`)
    - **frontend:** streamlit
    - **dev:** pytest, pytest-asyncio, ruff, mypy
  - Tool config: `[tool.ruff]`, `[tool.mypy]` (strict-ish, with the pydantic plugin), `[tool.pytest.ini_options]`.
- `uv.lock`: generated by uv.
- `Makefile`: `install`, `lint`, `format`, `typecheck`, `test`, `up`, `down`. The `eval` target is a placeholder that exits with "available in Phase 6".
- `.gitignore`, `.dockerignore`

### Application code
- `app/__init__.py`: holds `__version__`.
- `app/config.py`:
  - `Settings(BaseSettings)` holds every env var: LLM_MODEL, GROQ_API_KEY, OPENAI_API_KEY, GEMINI_API_KEY, JUDGE_MODEL, TAVILY_API_KEY, TAVILY_MCP_URL, DOCS_MCP_URL, QDRANT_URL, QDRANT_COLLECTION, EMBEDDING_MODEL, LANGFUSE_PUBLIC_KEY, LANGFUSE_SECRET_KEY, LANGFUSE_HOST, DATABASE_PATH, LOG_LEVEL, APP_VERSION, MAX_TOOL_CALLS, RUN_TIMEOUT_S, MAX_REVISIONS.
  - A cached `get_settings()`.
  - `require(*names)` raises `ConfigError("Missing required environment variable: GROQ_API_KEY")`.
  - Keys are optional at import time, so `/health` and CI work without secrets. Each feature calls `require()` when it starts.
- `app/logging.py`:
  - A stdlib-only JSON formatter and one `get_logger(name)`.
  - Fields whose names contain `key`, `secret` or `token` are redacted.
- `app/schemas.py`: the SPEC data contracts:
  - ResearchPlan, which validates that there are 3–6 sub-questions.
  - SubQuestion, EvidenceItem, Finding, Report, Section, Citation, ReviewResult.
  - The `JobStatus` Literal.
  - `ProgressEvent`: the SSE format `{job_id, type, agent, message, timestamp}`, with `type` as a Literal.
- `app/api/__init__.py`, `app/api/main.py`:
  - FastAPI app with `GET /health` returning `{"status": "ok", "version": ...}`.
  - `GET /metrics` in Prometheus format.
  - A middleware that records request count and latency.
- `app/cli.py`: a stub that prints usage through the logger ("available in Phase 3").
- Empty packages, each with a docstring: `app/agents/`, `app/tools/`, `mcp_servers/docs_mcp/`, `evals/`.
- `data/pdfs/.gitkeep`, `data/notes/.gitkeep`

### Tests (`tests/`)
- `test_config.py`: env loading, defaults, and `require()` naming the missing variable.
- `test_schemas.py`: valid and invalid cases for every model. For example, 2 or 7 sub-questions are rejected, and bad `language`, `source_type` or `confidence` values fail.
- `test_api_health.py`: TestClient checks for `/health` and `/metrics`.
- `test_logging.py`: output is valid JSON and secrets are redacted.

### Docker
- `docker/api.Dockerfile` is multi-stage:
  - **Builder:** the official uv image runs `uv sync --frozen --no-dev` (core group only).
  - **Runtime:** `python:3.12-slim` with a non-root `app` user.
  - A `HEALTHCHECK` calls `/health` with Python `urllib`, since there's no curl.
  - It runs `uvicorn app.api.main:app` on port 8000.
- `docker-compose.yml`:
  - **api:** built from the Dockerfile above. Uses `env_file: .env` and port 8000. Mounts `./data:/app/data:ro`. Waits until qdrant is healthy (`depends_on`).
  - **qdrant:** pinned `qdrant/qdrant` tag, a named volume and port 6333. The healthcheck is a bash `/dev/tcp` probe of `/readyz`, because the image has no curl.
- `.env.example`: every variable, with a placeholder value and a comment.

### CI
- `.github/workflows/ci.yml` runs on push and pull_request:
  - **Job `lint-test`:** setup-uv → `uv sync --frozen` (core + dev) → `ruff check` → `ruff format --check` → `mypy app mcp_servers` → `pytest`.
  - **Job `docker`:** `docker build -f docker/api.Dockerfile .`

   - `cp .env.example .env && docker compose up --build -d`
   - `curl -f localhost:8000/health` returns 200; `curl localhost:8000/metrics` and `curl localhost:6333/readyz` respond.
   - `docker compose ps` shows both services healthy.
6. You push, and CI goes green.
