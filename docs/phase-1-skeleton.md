# Phase 1 — Project skeleton, config, Docker, CI (detailed)

**Status:** planned. [Back to master plan](PLAN.md)

## Goal
Lay a clean foundation with no AI logic yet:
- reproducible dependencies, with **every** dependency group resolved and pinned now so that version conflicts show up early
- typed config
- JSON logging
- all data contracts
- a placeholder API with `/health` and `/metrics`
- Docker (api + Qdrant)
- lint/type/test tooling
- a GitHub Actions CI

## Definition of done
- `docker compose up --build` starts `api` + `qdrant`, and both report healthy.
- `curl -f localhost:8000/health` returns 200.
- `uv run ruff check .`, `uv run mypy app mcp_servers` and `uv run pytest` all pass locally.
- `uv sync --all-groups` resolves (all groups install together).
- CI is green after you push.

## Concepts explained before coding (3–5 sentences each)
uv, lockfiles and dependency groups; pydantic-settings; multi-stage non-root Docker images; GitHub Actions workflows.

## Files to create

### Project & tooling
- `pyproject.toml`:
  - Python `>=3.12,<3.13`.
  - Script entry point `researchcrew = app.cli:main` (a stub for now).
  - Exact versions come from `uv add` at implementation time and are copied into `DECISIONS.md`.
  - **Dependency layout.** uv dependency groups are *added on top of* the project dependencies, so the project dependencies stay light:
    - **`[project.dependencies]` (shared):** pydantic, pydantic-settings
    - **group `api`:** crewai, crewai-tools[mcp], mcp, litellm, fastapi, uvicorn[standard], httpx, qdrant-client, prometheus-client, tenacity, langfuse, openinference-instrumentation-crewai, openinference-instrumentation-litellm
    - **group `docs`:** mcp, qdrant-client, sentence-transformers, pymupdf, CPU-only torch (from the pytorch-cpu index via `[tool.uv.sources]`, `explicit = true`)
    - **group `frontend`:** streamlit, httpx
    - **group `dev`:** pytest, pytest-asyncio, ruff, mypy
  - If crewai's pins clash with litellm, openinference or langfuse, stop and report the conflict to you; don't work around it silently.
  - Tool config: `[tool.ruff]`, `[tool.mypy]` (strict-ish, with the pydantic plugin; `ignore_missing_imports` only for untyped third-party packages), `[tool.pytest.ini_options]`.
- `uv.lock`: generated by uv.
- `Makefile`: `install`, `lint`, `format`, `typecheck`, `test`, `up`, `down`. The `eval` target is a placeholder that exits with "available in Phase 6".
- `.gitignore`, `.dockerignore`

### Application code
- `app/__init__.py`: holds `__version__`.
- `app/config.py`:
  - `Settings(BaseSettings)` holds only the variables used **so far**: LLM_MODEL, GROQ_API_KEY, QDRANT_URL, QDRANT_COLLECTION, LOG_LEVEL, APP_VERSION. Each later phase adds its own variables and the matching `.env.example` lines.
  - A cached `get_settings()`. Tests clear the cache between cases.
  - `require(*names)` raises `ConfigError("Missing required environment variable: GROQ_API_KEY")`.
  - Keys are optional when the module is imported, so `/health` and CI work without secrets. **Entry points fail fast:** the API lifespan and the CLI call `require()` for the keys they need at startup. In Phase 1 the placeholder API needs no keys, so the list is empty; the call site exists and is tested.
- `app/log.py` (not `logging.py`, which would have the same name as the stdlib module):
  - A stdlib-only JSON formatter and one `get_logger(name)`.
  - **Redaction:**
    - an explicit list of sensitive field names: names ending in `_api_key` or `_secret_key`, plus `password` and `authorization`. Fields like `prompt_tokens` or `token_usage` are **not** redacted, because SPEC needs them logged.
    - every log string is also scrubbed of the actual secret values loaded in Settings and of URL query parameters such as `?apiKey=…`.
- `app/schemas.py`: the SPEC data contracts:
  - ResearchPlan, which validates that there are 3–6 sub-questions.
  - SubQuestion, EvidenceItem, Finding, Report, Section, Citation, ReviewResult.
  - **Wrappers for task outputs** (CrewAI `output_pydantic` needs a model, not a list): `EvidenceSet {items: list[EvidenceItem]}`, `FindingSet {findings: list[Finding]}`.
  - `Report.unanswered_sub_question_ids: list[str]`, so a report can state where every tool failed (SPEC error handling) instead of inventing an answer. This field is an addition to the SPEC contract; record it in DECISIONS.md.
  - The `JobStatus` Literal.
  - `ProgressEvent`: the SSE format `{job_id, type, agent, message, timestamp}`, with `type` as a Literal.
  - API models: `ResearchRequest {question (non-empty, max length), depth: Literal["quick","deep"] = "quick"}`, `JobCreated {job_id}`, `TokenUsage`, `JobResult {job_id, status, report, citations, token_usage, cost_usd, latency_s, error}`.
  - Conventions: all ids are `str`; timestamps are timezone-aware `datetime` (UTC).
- `app/api/__init__.py`, `app/api/main.py`:
  - FastAPI app with a lifespan that runs the startup key check.
  - `GET /health` returning `{"status": "ok", "version": ...}`.
  - `GET /metrics` in Prometheus format.
  - A small middleware with one request counter and one latency histogram (labelled by route and status).
- `app/cli.py`: a stub that logs usage through the logger ("available in Phase 3").
- Empty packages, each with a docstring: `app/agents/`, `app/tools/`, `mcp_servers/docs_mcp/`, `evals/`.
- `data/pdfs/.gitkeep`, `data/notes/.gitkeep`

### Tests (`tests/`)
- `test_config.py`: env loading, defaults, and `require()` naming the missing variable.
- `test_schemas.py`: valid and invalid cases for every model. For example, 2 or 7 sub-questions are rejected, bad `language`, `source_type`, `confidence` or `depth` values fail, and an empty question is rejected.
- `test_api_health.py`: TestClient checks for `/health` and `/metrics`.
- `test_logging.py`: output is valid JSON; `groq_api_key` is redacted; `prompt_tokens` is **kept**; a secret value or a URL `apiKey=` query inside a message is scrubbed.

### Docker
- `docker/api.Dockerfile` is multi-stage:
  - **Builder:** the official uv image runs `uv sync --frozen --no-dev --group api` (two steps: dependencies first for layer caching, then the project).
  - **Runtime:** `python:3.12-slim` with a non-root `app` user.
  - A `HEALTHCHECK` calls `/health` with Python `urllib`, since there's no curl.
  - It runs `uvicorn app.api.main:app --workers 1` on port 8000.
  - The final image size is written in DECISIONS.md (crewai's dependency tree is heavy, so don't expect a slim image).
- `docker-compose.yml`:
  - **api:** built from the Dockerfile above. Uses `env_file: .env` and port 8000. Mounts `./data:/app/data:ro`. Waits until qdrant is healthy (`depends_on`).
  - **qdrant:** pinned `qdrant/qdrant` tag, a named volume and port 6333. The healthcheck is a bash `/dev/tcp` probe of `/readyz`, because the image has no curl. Check that the pinned tag has bash before relying on this.
- `.env.example`: every variable used so far, with a placeholder value and a comment.

### CI
- `.github/workflows/ci.yml` runs on push and pull_request:
  - **Job `lint-test`:** setup-uv (with cache) → `uv sync --frozen --all-groups` → `ruff check` → `ruff format --check` → `mypy app mcp_servers` → `pytest`.
  - **Job `docker`:** `docker build -f docker/api.Dockerfile .` with GitHub Actions build cache (`docker/build-push-action`, `cache-from/to: type=gha`).

   - `docker image ls` → record the api image size.
